Current onboarding and trip access · reviewed 2026-10-15

Create a trip, or join one from a link

Trip creation and invite previews work without asking for email first. Email-code verification unlocks organizer changes and invitee details. Postgres row-level security remains the data access boundary.

Organizer: create and verify

Welcome

At /, choose Create your first trip. Returning users can sign in with an email code and open /trips.

Name the trip

At /trip/new, choose a name and optional trip details. On first use, the app creates an anonymous Supabase session when the form is submitted.

Trip workspace

create_trip() stores the trip under that session. The owner can view it; write actions stay gated until email verification.

Verify by email code

The inline prompt sends a six-digit code. Anonymous owners link the email to their session; existing accounts use the sign-in path. Verification unlocks organizer actions.

From the trip workspace, the organizer can copy a shared invite link or open their own email app with a prefilled invitation. Splitiful does not send or store the invitee’s email address.

Invitee: preview, verify, and join

Open the invite

/join/[code] loads a public trip summary through the rate-limited invite endpoint.

Choose an action

The preview shows totals and balances. See full details or add an expense to continue to email verification.

Confirm email

/check-email sends a six-digit code. A first-time visitor gets an anonymous session that is linked to the email; an existing account signs in.

Join the workspace

After verification, the app collects a display name if needed, creates membership, and opens /trip/[id] with the requested details or action.

A visitor who opens a trip page directly can also see its public summary. Joining from that route uses the trip ID and join_trip_by_id(); invite-code joins use the corresponding invite flow.
